# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | 古い形式（Hive）のテーブルを、新しい形式（Iceberg）の S3 Tables に、本番を止めずに移行してくれる機能ができた |
| **料金** | コピーしたデータの分だけ。変換そのものは無料 |
| **対象** | 東京・ムンバイ・シンガポール・シドニー、バージニア北部・オハイオ・オレゴン、フランクフルト・アイルランド・ストックホルムの 10 リージョン |

:::details そもそも Hive テーブルと Iceberg、S3 Tables とは？
| 名前 | ひとことで |
|---|---|
| データレイク | いろいろなデータをとりあえず S3 にためておき、あとから分析する置き場 |
| Apache Hive テーブル | S3 のフォルダを「表」として扱う昔からのやり方。ファイルの一覧や更新の管理が苦手 |
| Apache Iceberg | 表の変更履歴やファイルの一覧をきちんと管理する、新しいテーブルの形式[^iceberg] |
| Amazon S3 Tables | Iceberg のテーブルを置くための、S3 の専用の入れ物 |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 移行の方法 | テーブルごとにパイプラインを作って、何週間もかけて移す | S3 Tables が検証・変換・コピーをしてくれる。本番の処理は動かしたまま |
| 安心の仕組み | ― | 各ステップを確認でき、移行元の変更を何度でも同期でき、移行元に戻す（ロールバック）こともできる |
| 圧縮 | ― | Snappy で圧縮されたデータは ZSTD で圧縮し直してまとめるので、容量やファイル数が減り、検索も速くなる |
| 使い方 | ― | コンソール、移行用の API、Agent Toolkit for AWS の移行スキル（AI エージェントに任せる） |

**どんなときにうれしい？**
昔作った Hive のテーブルが多くて Iceberg に移したいけれど、1 つずつ移行の仕組みを作る手間が大きくて手を付けられていないとき。

:::message alert
今のところ、移行元は AWS Glue に登録された Hive テーブルで、データが Parquet 形式のものだけです。同じアカウント・同じリージョンの中でしか移行できません。
:::

:::message
**確認ポイント**
S3 コンソール → テーブルバケットの画面で、移行（migration）の機能を探す
キーワード: S3 Tables managed migration Hive to Iceberg
:::
