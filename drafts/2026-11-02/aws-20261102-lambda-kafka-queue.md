# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | 自分で用意した Kafka から Lambda で読むときに、「キュー」のモードを選べるようになり、パーティションの数を超えて並列に処理できるようになった |
| **料金** | Lambda の通常の料金。プロビジョンドモードを使う場合はイベントポーラーユニット（EPU）の料金も |
| **対象** | セルフマネージド Kafka のイベントソースマッピングが使えるすべての商用リージョン。Confluent Cloud なども含む |

:::details そもそも Kafka と Lambda のイベントソースマッピングとは？
| 名前 | ひとことで |
|---|---|
| Apache Kafka | 大量のメッセージを順番に貯めて、いろいろなプログラムに配るためのソフト |
| パーティション | Kafka のメッセージの置き場所を分けたもの。これまでは 1 つのパーティションを読めるのは同時に 1 つだけで、並列度の上限になっていた |
| share group | Kafka 4.2 で一般提供になった仕組み。1 つのパーティションを複数の読み手で分け合える（Kafka を「キュー」として使える） |
| イベントソースマッピング（ESM） | Kafka などからメッセージを取ってきて Lambda を呼び出す、Lambda 側の仕組み |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 並列度 | パーティションの数まで | 1 つのパーティションを複数のポーラーで同時に読める（ポーラーごとに最大 10 の同時呼び出し） |
| 遅い・失敗したメッセージ | 同じパーティションの後ろのメッセージが待たされる | ほかのメッセージは止まらずに進む |
| 設定 | ― | ESM を作るときに ConsumptionMode を Queue にする。送る側・トピック・関数のコードは変えなくてよい |

**どんなときにうれしい？**
アクセスが急に増えたときにメッセージが溜まってしまうが、パーティションを増やすのは大変、というとき。順番を気にしない処理（通知の送信、画像の変換など）なら、Lambda 側だけで並列度を上げられます。

:::message alert
キューのモードでは、パーティションの中の順番は守られません。順番が大事な処理には向きません。また、Apache Kafka 4.2 以降など、share group を有効にしたクラスターが必要です。
:::

:::message
**確認ポイント**
Lambda コンソール → 関数 → トリガーを追加 → 「Apache Kafka」で、ConsumptionMode（Queue）の設定を探す
キーワード: Lambda Kafka ConsumptionMode Queue share group
:::
