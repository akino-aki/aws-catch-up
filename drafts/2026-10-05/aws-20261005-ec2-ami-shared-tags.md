# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | タグのキーに `ec2:SharedTag/` を付けると、AMI の共有先でもそのタグが見えるようになった |
| **料金** | 追加料金なし |
| **対象** | すべてのリージョン |

:::details そもそも AMI とタグとは？
| 名前 | ひとことで |
|---|---|
| AMI（Amazon Machine Image） | EC2 のサーバーを作るときの「ひな形」。OS や設定済みのソフトが入っている |
| AMI の共有 | 作った AMI を、ほかの AWS アカウントや組織全体、または一般公開で使えるようにすること |
| タグ | リソースに付ける「キー＝値」のラベル。`version=1.2` や `approved=true` など |

これまでは、AMI を共有してもタグは相手からは見えませんでした。
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 共有先からタグが見えるか | 見えない | `ec2:SharedTag/` で始まるキーのタグは見える |
| タグを相手に届ける方法 | SNS ＋ Lambda などで相手側にタグを複製する仕組みを自作 | タグが AMI と一緒に自動で届く |
| 共有先での操作 | ― | 読み取りのみ。変更・削除は持ち主だけ |
| タグの上限 | ― | 持ち主側の「1 リソース 50 個」にだけ数えられる。共有先は自分用のタグを別に付けられる |

**どんなときにうれしい？**
組織で「承認済みのひな形 AMI」を配っているとき。共有先のアカウントからも「バージョン」「承認済みかどうか」「サポート期限」などをタグで確かめられるので、古い AMI を使ってしまうミスを減らせます。

:::message
**確認ポイント**
EC2 コンソール →「AMI」→ 共有されている AMI を選んで「タグ」タブ
キーワード: ec2:SharedTag, AMI sharing
:::
