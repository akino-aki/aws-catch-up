# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | イメージ作成のたびに新しいサーバーを立ち上げて待つ代わりに、Auto Scaling グループ（ASG）で動いているサーバーを使えるようになり、作成が速くなった |
| **料金** | 追加料金なし |
| **対象** | すべてのリージョン。使うかどうかは自分で選ぶ（オプトイン） |

:::details そもそも EC2 Image Builder と ASG とは？
| 名前 | ひとことで |
|---|---|
| AMI | EC2 のサーバーを作るときの「ひな形」。OS や入れておいたソフトがまるごと入っている |
| EC2 Image Builder | AMI づくりを自動化するサービス。「この OS にこのソフトを入れて、テストして、AMI にする」をパイプラインとして繰り返せる |
| ビルドコンポーネント | Image Builder で「何を入れるか・何を設定するか」を書いた手順のまとまり |
| Auto Scaling グループ（ASG） | 決めた台数の EC2 を保ち、減ったら自動で補充してくれる仕組み |
| インフラストラクチャ設定 | Image Builder が作業用のサーバーをどう用意するか（インスタンスタイプ・ネットワークなど）を決める設定 |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 作業用のサーバー | 毎回新しく起動し、起動と初期化が終わるのを待つ | ASG で動いているサーバーを 1 台取り出してすぐ作業 |
| サーバーの補充 | ― | ASG が台数を保とうとして自動で補充するので、次の実行にも使える |
| 設定 | ― | インフラストラクチャ設定で ASG を指定するだけ。指定しないパイプラインは今までどおり |

**どんなときにうれしい？**
セキュリティパッチを当てた AMI を毎日作り直すなど、パイプラインをよく回す場合です。起動待ちの時間が毎回なくなるので、イメージができあがるまでの時間が短くなり、作り直しの回数を増やしやすくなります。

:::message alert
Image Builder 自体の料金はかかりませんが、ASG で待機させておくサーバーの EC2 料金はかかります。待機させる台数と、起動を待つ時間のどちらを取るかを考える必要があります。
:::

:::message
**確認ポイント**
EC2 Image Builder コンソール → インフラストラクチャ設定 → ASG（親インスタンス）の指定欄
キーワード: EC2 Image Builder infrastructure configuration Auto Scaling group, parent instances
:::
