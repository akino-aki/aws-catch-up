# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | 移行を手伝う AWS Transform のネットワーク移行に、「ゼロから新しく作る」「ファイアウォールのルールをセキュリティグループにして既存の VPC に入れる」の 2 つのやり方が加わった |
| **料金** | What's New には記載なし（週刊AWS の紹介では AWS Transform 自体は無料） |
| **対象** | すべての商用リージョンと GovCloud リージョンへの移行 |

:::details そもそも AWS Transform とは？
| 名前 | ひとことで |
|---|---|
| AWS Transform | オンプレミスや古いシステムを AWS に移すときの調査・設計・変換を、AI エージェントが手伝ってくれるサービス |
| VPC | AWS の中に作る、自分専用のネットワーク |
| セキュリティグループ | EC2 などに付ける「どこからの通信を通すか」の決まり。サーバーごとの門番 |
| オンプレミスのファイアウォールルール | 会社のデータセンターなどで使っている、通信を通す・止めるの決まり |
:::

**今回なにが変わった？**

| やり方 | 内容 |
|---|---|
| ① 今あるネットワークを移す（これまでもあった） | 今のネットワーク構成を読み取り、新しい VPC に置き換えて移す |
| ② 新しく作る（新しい） | 今の構成ファイルがなくても、AWS のベストプラクティスに沿ったネットワークを一から設計・構築する |
| ③ ルールだけ変換する（新しい） | オンプレミスのファイアウォールルールをセキュリティグループに変換し、すでにある VPC に入れる。ネットワーク全体は作り直さない |

③ では、ただ置き換えるだけでなく、使われていない古いルールを見つけたり、もっと良い書き方を提案したりもします。

**どんなときにうれしい？**
すでに AWS にネットワークがあって、オンプレミスのサーバーを少しずつ移していく場合です。長年増え続けて誰も全体を把握していないファイアウォールのルールを、移行のついでに整理できます。逆に、今の構成をまねる必要がない場合は、② で最初からきれいなネットワークを作れます。

:::message
**確認ポイント**
