# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | Redshift に、最新のスナップショットを指定した別のリージョンへ自動で、続けて、差分だけコピーする機能が加わった |
| **料金** | Redshift の料金ページの「バックアップとストレージ」「データ転送」を参照 |
| **対象** | プロビジョンドクラスターと Serverless のワークグループ。すべての商用リージョンと GovCloud (US) |

:::details そもそも Redshift のスナップショットとは？
| 名前 | ひとことで |
|---|---|
| Amazon Redshift | 大量のデータを集計・分析するためのデータウェアハウス |
| スナップショット | ある時点のデータを丸ごと保存したバックアップ |
| クロスリージョンコピー | スナップショットを別のリージョンにもコピーしておくこと。リージョンごと使えなくなったときに備える |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| コピーされるもの | スナップショットのスケジュールに合わせて作られたもの | 常にその時点で最新のスナップショット（スケジュールに左右されない） |
| 障害が起きたとき | 手でコピーを始める必要があることも | 何もしなくてよい |
| コピーの仕方 | ― | 続けて、差分だけ |
| コピー先の名前 | ― | 頭に `copy` が付く |

**どんなときにうれしい？**
リージョン全体の障害に備えて、別のリージョンに新しいバックアップを常に置いておきたいとき。いざというときは、コピー先のスナップショットから新しいクラスターや Serverless のワークグループに復元できます。

:::message alert
クラスターごとにこの機能をオンにして、コピー先のリージョンと保存期間を設定する必要があります。別リージョンへのデータ転送とストレージの料金がかかります。
:::

:::message
**確認ポイント**
Redshift コンソール → クラスター（またはワークグループ）→ バックアップの設定で、クロスリージョンスナップショットの自動コピーとコピー先・保存期間
キーワード: Redshift automated cross-region snapshot copy
:::
