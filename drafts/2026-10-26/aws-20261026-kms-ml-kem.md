# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | KMS で、ポスト量子暗号[^pqc]の鍵カプセル化方式 ML-KEM（NIST FIPS 203）の鍵を作り、2 者の間で共有の秘密を作れるようになった |
| **料金** | What's New には記載なし（KMS の通常の料金体系） |
| **対象** | KMS が使えるリージョン（UAE・バーレーン・中国のリージョンを除く） |

:::details そもそも KMS と鍵カプセル化とは？
| 名前 | ひとことで |
|---|---|
| AWS KMS | 暗号の鍵を安全に作って保管し、鍵を外に出さずに暗号の操作をしてくれるサービス |
| 鍵カプセル化（KEM） | 相手の公開鍵で「共有の秘密」を包んで送り、相手だけが秘密鍵で取り出せるようにする方法。取り出した秘密を使って通信を暗号化する |
| ML-KEM | 量子コンピュータでも解きにくい数学の問題をもとにした KEM。NIST が FIPS 203 として標準にした |
| HSM | 鍵を外に出さずに守る専用のハードウェア |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 鍵の共有に使える方式 | RSA や ECDH など、従来の方式 | ＋ ML-KEM（512 / 768 / 1024 の 3 種類） |
| 使う API | ― | Encapsulate（公開鍵で 32 バイトの共有の秘密とその暗号文を作る）／ Decapsulate（秘密鍵で暗号文から共有の秘密を取り出す） |
| 秘密鍵の保管 | ― | FIPS 140-3 レベル 3 の認定を受けた HSM の中 |
| 公開鍵 | ― | GetPublicKey で取り出して相手に配り、相手は AWS-LC・OpenSSL などで手元で包める |

**どんなときにうれしい？**
「今のうちに通信を記録しておき、将来の量子コンピュータで解読する（harvest now, decrypt later）」という攻撃に備えたいとき。アプリどうしで鍵を共有する部分を、量子コンピュータに強い方式に置き換えられます。

:::message

キーワード: KMS ML-KEM, Encapsulate, Decapsulate, FIPS 203
