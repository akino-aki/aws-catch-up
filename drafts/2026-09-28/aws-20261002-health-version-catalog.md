# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | AWS で使うソフトウェアのバージョンと、そのサポート期限を一覧で見られるようになった |
| **料金** | 記載なし |
| **対象** | すべての商用リージョン |

:::details そもそも AWS Health とは？
AWS の障害やメンテナンス、「このバージョンはサポートが終わります」といった、自分のアカウントに関係するお知らせを確認できるサービスです。
:::

**今回なにが変わった？**
**version catalog** が追加されました。最初の対象は次の 3 つで、今後増える予定です。

| サービス | 確認できるもの |
|---|---|
| RDS | データベースエンジンのバージョン |
| EKS | Kubernetes のバージョン |
| Lambda | ランタイム（Python や Node.js のバージョンなど） |

**どんなときにうれしい？**
「来年サポートが切れるから、今のうちにアップグレードを計画しよう」と、期限が近づく前に余裕を持って計画を立てられます。

:::message alert
ダッシュボードは誰でも見られますが、API で使うには上位のサポートプラン（Business Support+ 以上）が必要です
:::

:::message
**確認ポイント**
AWS Health Dashboard →「Version Catalog」
:::

# ✍️ 自分の調査・勉強結果

**画面**

AWS Health Dashboard の左メニュー「アカウントの状態」の中に「バージョンカタログ」がありました。公式発表では対象は RDS・EKS・Lambda の 3 つでしたが、画面の一覧の先頭には Bedrock のモデル（AI21 Labs Jamba 1.5 や Amazon Nova など）が並んでいて、次のマイルストーン（Extended Support End など）、日付、影響リスク、ステータス（Within 90 days など）が見られました。

![AWS Health のバージョンカタログ](/images/aws-20261002-health-version-catalog/health-version-catalog.png)

**「スケジュールされた変更」との違い**

サポート終了などの通知は、これまでも届いていて、Health Dashboard の「スケジュールされた変更」でも一覧で見られました。何が違うのかを整理しました。

| | スケジュールされた変更（通知の一覧） | バージョンカタログ |
|---|---|---|
| 見られる範囲 | 自分のアカウントで使っているリソースに関係するものだけ | 使っていないものも含めて、サービスのバージョン全部 |
| 出てくるタイミング | 期限が近づいて、AWS が通知を出してから | 最初から全部載っている |
| 役割 | やることリスト（自分の環境で対応が必要なもの） | 予定表（どのバージョンがいつまで使えるか） |

これまで同じような情報は、Lambda のランタイムの表、RDS のリリースカレンダー、EKS のバージョンのカレンダーなど、各サービスのドキュメントにばらばらに載っていました。それが Health の 1 か所に、同じ形式でまとまったのが今回のアップデートです。

**使うとしたら、どんなときか**

サポート終了の通知は今までどおり届くので、日々の運用は通知に任せたままでよさそうです。バージョンカタログを見るのは、次のようなタイミングだと思います。

- **新しいサービスやバージョンを使い始めるとき**: いちばん長く使えるバージョンを選ぶ。通知は使い始めてからしか来ないので、ここはカタログでしかできない
- **予算を考えるとき**: 次の期間に期限を迎えるものを洗い出して、アップグレードの作業を予定に入れる。影響リスクの `BILLING`（使い続けると延長サポートなどの追加料金がかかる）は、作業費と比べる材料になる

API（`aws health describe-service-lifecycle`）を使えば、CI/CD で期限間近のランタイムを止めるなどの自動化もできます。ただ、API はビジネスサポート+ 以上でないと使えません。

画面で見る分には、しょっちゅう開くものではなく、必要なときに思い出せればよい機能、という印象です。
