# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | シークレットの複製（レプリカ）を、別の AWS アカウントに置いて、自動で同期できるようになった |
| **料金** | 発表には記載なし（Secrets Manager の料金ページを参照） |
| **対象** | Secrets Manager が使えるすべてのリージョン |

:::details そもそも AWS Secrets Manager とは？
| 名前 | ひとことで |
|---|---|
| AWS Secrets Manager | パスワードや API キーなどの秘密の情報（シークレット）を、安全に保管するサービス |
| ローテーション | パスワードなどを定期的に自動で変えること |
| AWS KMS | 暗号化の鍵を管理するサービス。シークレットはこの鍵で暗号化される |
| レプリケーション | 元のデータの複製を別の場所に作って、同じ内容に保つこと。これまでも別のリージョンにはできた |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 別のアカウントから使う方法 | 元のアカウントのシークレットを直接参照する。シークレットのポリシー、利用側の IAM ポリシー、KMS の鍵のポリシーの 3 か所で許可が必要 | 利用側のアカウントに複製を置き、そこを読む。鍵の共有やアカウントをまたぐポリシーはいらない |
| 複製の暗号化 | ― | 複製を置くアカウントが持つ KMS の鍵（カスタマーマネージドキー）で暗号化される |
| 更新の反映 | ― | 元の値が変わると（ローテーションも含めて）自動で複製も更新される |
| もしものとき | ― | 複製を、独立したシークレットに昇格できる |

**どんなときにうれしい？**
複数のアカウントで同じデータベースのパスワードを使うとき。管理は 1 つのアカウントでまとめて行い、各アカウントは自分のところの複製を読むだけで済みます。元のアカウントが乗っ取られたりランサムウェア[^ransom]の被害にあったりしたときに備えて、復旧用のアカウントに複製を置いておく使い方もできます。

:::message
**確認ポイント**
Secrets Manager コンソール → シークレット → レプリケーションの設定で、別のアカウントを指定する
キーワード: Secrets Manager cross-account replication, AssociateCrossAccountReplica
:::
