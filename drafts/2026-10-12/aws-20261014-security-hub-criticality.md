# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | Security Hub で、リソースごとに「どれくらい大事か（重要度）」を付けて、危ないものの中から大事なリソースのものを先に対応できるようになった |
| **料金** | Security Hub Essentials に含まれ、追加料金なし |
| **対象** | Security Hub が使えるすべてのリージョン。全員に最初から有効 |

:::details そもそも Security Hub とエクスポージャーとは？
| 名前 | ひとことで |
|---|---|
| AWS Security Hub | AWS 環境のセキュリティの問題を 1 か所に集めて見せてくれるサービス |
| エクスポージャー | 「外から攻撃されうる状態」のこと。複数の弱点の組み合わせから見つけられる |
| リソース重要度 | そのリソースが止まったり漏れたりしたときの影響の大きさ |
| 自動化ルール | 条件に合う検出結果やリソースに、決まった設定を自動で付けるルール |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 優先順位の決め方 | 危険度などから決める | ＋ リソースの重要度も考えられる |
| 重要度の付け方 | ― | 自動化ルールで指定（例: このアカウントのコンピュートリソースは全部「Very High」） |
| 何も設定しないとき | ― | タグとリソース名から自動で推測し、何から決めたかも記録する |
| 表示 | ― | Resources ページの列、エクスポージャーの Impact assessment タブ。並べ替え・絞り込み・グループ化ができる |

**どんなときにうれしい？**
検出結果が多すぎて、どこから手をつけたらよいか分からないとき。本番環境のアカウントだけ重要度を上げておけば、本番に関わる問題が上に来るので、限られた時間で大事なところから直せます。ルールは、これから見つかるリソースにも自動で当てはまります。

:::message
**確認ポイント**
Security Hub コンソール → Resources ページの重要度の列、エクスポージャーの検出結果 → Impact assessment タブ、自動化ルール
キーワード: Security Hub resource criticality, exposure prioritization
:::
