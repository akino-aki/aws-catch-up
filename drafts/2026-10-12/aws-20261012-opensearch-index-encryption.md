# 🤖 AIの解説

| 項目 | 内容 |
|---|---|
| **要約** | 1 つのドメインの中で、インデックスごとに別々の KMS キーで保存データを暗号化できるようになった |
| **料金** | 機能自体は追加料金なし（KMS と OpenSearch Service の通常の料金） |
| **対象** | OpenSearch 3.3 以降の新しいドメイン。東京を含む 14 リージョン |

:::details そもそも OpenSearch Service とは？
| 名前 | ひとことで |
|---|---|
| Amazon OpenSearch Service | 大量の文章やログを、すばやく全文検索・集計できる検索エンジンのマネージドサービス |
| ドメイン | OpenSearch のクラスター 1 つ分。サーバーの集まりのこと |
| インデックス | ドメインの中のデータの入れ物。データベースでいう「テーブル」に近い |
| AWS KMS | 暗号化に使う「鍵」を作って管理するサービス |
| カスタマーマネージドキー | 自分で作って、使える人や無効化のタイミングを自分で決められる KMS の鍵 |
:::

**今回なにが変わった？**

| | これまで | これから |
|---|---|---|
| 暗号化キーの単位 | ドメイン全体で 1 つ | インデックスごとに別のキーを選べる |
| テナントごとに鍵を分けたいとき | ドメインを分ける必要があった | 1 つのドメインのまま分けられる |
| 設定の流れ | ドメイン作成時に鍵を 1 つ指定 | 作成時に暗号化モードを「Native」にして鍵を指定 → 追加の鍵をドメインに登録 → インデックスごとに使う |

**どんなときにうれしい？**
複数のお客さん（テナント）のデータを 1 つの検索基盤にまとめているサービスで、「お客さんごとに鍵を分けたい」「解約したお客さんの鍵だけ無効にしたい」という場合。ドメインを何個も作らずに済むので、サーバー代や運用の手間を抑えられます。

:::message alert
発表で手順が書かれているのは**新しいドメイン**を作るときだけです。既存のドメインで使えるかは、ドキュメントで確認しましょう。鍵を増やすと、その分 KMS の鍵の料金と API 呼び出しの料金がかかります。
:::

:::message
**確認ポイント**
OpenSearch Service コンソール →「ドメインの作成」→ 暗号化の設定（暗号化モード）
キーワード: index-level encryption, Native encryption mode, customer managed key
:::
