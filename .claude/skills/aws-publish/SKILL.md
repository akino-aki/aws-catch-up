# aws-publish

aki が書き終えた記事を、レビューしてから PR にする。**マージ（＝ Zenn への公開）は aki が PR とプレビューを見てから行う。** このスキルは自動でマージしない。

公開は aki が頼んだときだけ行う。✍️ 欄が書かれていても、頼まれていない記事は公開しない。

## 1. 対象の記事を決める

```bash
git switch work
git pull --ff-only
npm run check
```

- `$ARGUMENTS` や aki の言葉から、`drafts/<週>/` または `articles/` のどの記事かを決める。迷ったら一覧を見せて確認する
- 記事に未コミットの変更があれば、それも含めて公開してよいか確認する（PR を作るときにコミットされる）
- ほかのファイルの未コミットの変更は、aki の作業中のものなので触らない

## 2. 機械的なチェック

```bash
npm run check -- --lint
```

記事の形の NG と、✍️ 欄が空でないかを確かめる。✍️ 欄が空なら公開できないので、aki に伝えて終了する。

## 3. レビュー

記事の本文と、記事が使っている画像（`images/<slug>/`）を**すべて**読んで確かめる。画像は Read で開いて中身を見る。

| 観点 | 確かめること |
|---|---|
| 個人情報 | aki の本名、普段使いのメールアドレス、塗りつぶされていないアカウント ID・ARN・IP アドレス（文書用の例示アドレス 192.0.2.0/24・198.51.100.0/24・203.0.113.0/24 は可）・アクセスキー・ユーザー名・組織 ID・URL など。Windows のユーザーフォルダのパス（`C:\Users\...`）にも本名が含まれる |
| 画像 | 上の個人情報が写っていないか。AWS コンソールのヘッダー（アカウント名・メールアドレス）が写っていないか |
| 誤字脱字・文章 | 誤字、脱字、変換ミス、意味の通らない文、表記の揺れ |
| 書き方 | 個人の学習記録として書かれているか。会社や業務を前提にした表現（「会社の検証環境」「業務では」など）がないか |
| 事実 | AI の解説と ✍️ 欄の内容が食い違っていないか。食い違っていたら、どちらが正しいかを確かめて指摘する |
| タイトル | AWS のアップデートのタイトル（What's New の見出し）をそのまま、または言い換えただけになっていないか。「〈サービス〉の新機能「〈機能名〉」を試してみた」のように、✍️ 欄で aki が実際にやったこと（試した・調べた・比べた など）が伝わるか。なっていなければ、✍️ 欄の内容に合わせたタイトルの案を 2〜3 個出して、aki に選んでもらう |

本名や普段使いのメールアドレスは、見つけたことを伝えるだけにして、チャットにもファイルにも書き写さない。

### 指摘があったら

- 指摘と直し方の案を aki に見せる。**aki が OK した直しだけ**を記事に反映する（✍️ 欄は aki の文章なので、勝手に書き換えない）
- 個人情報が写った画像は、Claude には加工できない。aki に差し替えを頼み、差し替わるまで PR を作らない

## 4. PR を作る

レビュー結果を PR の本文として、作業用のファイル（スクラッチパッドなど、リポジトリの外）に書き、公開スクリプトに渡す。

```bash
npm run publish -- <slug> --body-file <PR の本文のファイル>
```

PR の本文の形:

```markdown
## 記事
- タイトル: <タイトル>
- ファイル: `articles/<slug>.md`（新規公開 / 公開済みの記事の更新）
- 元のアップデート: <What's New の URL>

## レビュー結果
| 観点 | 結果 |
|---|---|
| 個人情報（本文） | ✅ 問題なし / ⚠️ <内容> |
| 個人情報（画像 N 枚） | ✅ 問題なし / ⚠️ <内容> |
| 誤字脱字・文章 | ✅ 問題なし / 修正済み: <何をどう直したか> |
| 書き方（個人の学習記録） | ✅ 問題なし / ⚠️ <内容> |
| 事実の食い違い | ✅ 問題なし / ⚠️ <内容> |
| タイトル（アップデートのタイトルそのままになっていないか） | ✅ 問題なし / 変更済み: <前> → <後> |

## 確認してほしいこと
- <aki に目で見てほしい点があれば。なければ「特になし」>

## マージの前に
- [ ] PR の差分（Files changed）を確認した
- [ ] Zenn のプレビューで見た目を確認した
```

本文に本名や普段使いのメールアドレスを書かない（PR は public）。

## 5. プレビューを開く

公開スクリプトで記事が `articles/` に移ったので、Zenn のプレビューで見られる。

- `.claude/launch.json` の `zenn-preview`（http://localhost:8000）を起動し、`/articles/<slug>` を開く
- aki に、PR の URL とプレビューの URL を伝え、確認してからマージしてもらう

```
PR: https://github.com/akino-aki/aws-catch-up/pull/N
プレビュー: http://localhost:8000/articles/<slug>
確認できたら、GitHub で「Merge pull request」を押すか、「マージして」と言ってください。
```

## 「マージして」と言われたら

```bash
gh pr merge <PR の番号> --merge --auto
```

- CI のチェックがまだ終わっていなければ、終わり次第マージされる。チェックが失敗したらマージされないので、原因を調べて aki に伝える
- チェックを回避したり、マージを強行したりしない
- マージされると Zenn に反映される。数分かかることがある

## 公開をやめるとき

PR をマージせずに閉じればよい。ただし `work` では記事が `articles/` に移っているので、下書きに戻すなら `articles/<slug>.md` を元の `drafts/<週>/` に戻して `published: false` にし、コミットする。
