# aws-publish

aki が書き終えた記事をレビューして、公開用の PR を作る。

この記事は public な GitHub と Zenn に出る。一度公開した個人情報は取り消せないので、公開の前に Claude がレビューし、最後は aki 自身が PR とプレビューを見てからマージする、という二重の確認にしている。そのため、このスキルは**自動でマージしない**。PR を作り、プレビューを開いて、aki の判断を待つところまでが役目。

公開の手続きを始めるのは、aki が頼んだときだけ。✍️ 欄が書かれていても、頼まれていない記事は公開しない。push 済みでも、aki がまだ書き足すつもりかもしれないため。

運用の全体像は `docs/workflow.md`、記事の書き方のルールは `CLAUDE.md` にある。

## 全体の流れ

```
1. 対象を決める      どの記事を公開するか確かめる
2. 機械的なチェック  記事の形と、✍️ 欄が空でないか
3. レビュー          個人情報・誤字脱字・書き方・事実・タイトル
4. PR を作る         レビュー結果を本文に書く（自動マージはしない）
5. プレビューを開く  PR とプレビューの URL を aki に伝える
   ↓
   aki が確認してマージ（「マージして」と言われたら、下の手順で）
```

## 1. 対象を決める

```bash
git switch work
git pull --ff-only
npm run check
```

- `$ARGUMENTS` や aki の言葉から、`drafts/<週>/` または `articles/`（公開済みの記事の更新）のどの記事かを決める。候補が複数あれば、一覧を見せて確かめる
- 記事に未コミットの変更があれば、それも含めて公開してよいか確かめる。PR を作るときにコミットされるため
- ほかのファイルの未コミットの変更には触らない。aki が書きかけているものなので

## 2. 機械的なチェック

```bash
npm run check -- --lint
```

記事の形の NG と、✍️ 欄が空でないかを確かめる。✍️ 欄が空なら公開できないので、aki に伝えて終わる。

## 3. レビュー

`references/review-checklist.md` を読み、その観点で記事の本文と画像をすべて確かめる。

- 指摘があれば、直し方の案を見せて aki に確かめ、OK が出た直しだけを反映する
- タイトルが「アップデートのタイトルそのまま」なら、✍️ 欄の内容に合わせた案を 2〜3 個出して選んでもらう
- 個人情報が写った画像は加工できないので、aki に差し替えを頼み、差し替わるまで PR を作らない
- 本名や普段使いのメールアドレスは、見つけた場所だけを伝え、どこにも書き写さない

## 4. PR を作る

`references/pr-body.md` の型で、レビュー結果を PR の本文として書く。本文のファイルはリポジトリの外（スクラッチパッドなど）に置く。リポジトリに入れると、ほかのコミットに紛れ込むため。

```bash
npm run publish -- <slug> --body-file <PR の本文のファイル>
```

スクリプトが行うこと:

- 下書きなら `drafts/<週>/` から `articles/` に移して `published: true` にする（公開済みの記事なら、今の内容のまま）
- `work` にコミットして push する
- `main` に、この記事とその画像だけを足した `publish/<slug>` ブランチを作り、`main` への PR を作る。ほかの記事の書きかけは PR に入らない

## 5. プレビューを開く

記事が `articles/` に移ったので、Zenn のプレビューで見られる。`.claude/launch.json` の `zenn-preview`（http://localhost:8000）を起動し、`/articles/<slug>` を開く。

aki には次のように伝え、確認を待つ。

```
PR: https://github.com/akino-aki/aws-catch-up/pull/N
プレビュー: http://localhost:8000/articles/<slug>
確認できたら、GitHub で「Merge pull request」を押すか、「マージして」と言ってください。
```

## 「マージして」と言われたら

```bash
gh pr merge <PR の番号> --merge --auto
```

- CI のチェックが終わっていなければ、終わり次第マージされる
- チェックが失敗したらマージされない。原因を調べて aki に伝える。チェックを回避したり、マージを強行したりしない。チェックは、✍️ が空の記事などが公開されるのを防ぐためのもの
- マージされると、数分で Zenn に反映される

## 公開をやめるとき

PR をマージせずに閉じる。`work` では記事が `articles/` に移っているので、下書きに戻すなら `articles/<slug>.md` を元の `drafts/<週>/` に戻し、`published: false` にしてコミットする。
