AIに作ってもらったスクリプトを自分で読めるようになりたくて、Claudeに課題を出してもらい、bashの基礎を学び直しました。

でも基礎は学べました。昔プログラミングを学び始めたときにちょっと触れたころは難しくてキツイ・・・って思ったけど、今はすんなり理解できて、成長を感じてちょっと嬉しかったです。

# なんで学ぼうと思ったのか

コマンドラインで作業していると、同じ操作を何度も繰り返すときに、その場で関数を作ってまとめたりしますよね。
なんとなくこういうことをしている、というのは分かっていたけど、しっかり理解はしていませんでした。

AIが発達してきて、今までなら作るのも覚えるのもコストの方が高くついていたような作業でも、AIにスクリプトを作ってもらって使うことが増えました。
たとえば、AWSのParameter Storeの新しいデータ型を試していたときは、値を次々に試すために、Claudeにこんな関数を作ってもらいました。

```bash
try() { n="/catchup-test/a/${1//:/-}"; if aws ssm put-parameter --name "$n" --type "${3:-String}" --data-type "$1" --value "$2" --overwrite >/dev/null 2>/tmp/err; then echo "OK  $1 [$2]"; else echo "NG  $1 [$2] $(cat /tmp/err)"; fi; }
```

プログラミングの基礎は分かるので、`try()`のあとが関数の中身だろうな、`if` `then` `else`もなんとなく分かる…という、分かるような分からない絶妙なライン。
`n="/catchup-test/a/${1//:/-}"`、`"OK  $1 [$2]"`、`$(cat /tmp/err)`あたりはさっぱりでした。
`>/dev/null 2>/tmp/err`も、終了コードが0だったり、入出力に1や2の番号があったりするから、そういうやつかなぁ…出力を`/tmp/err`に入れてる的な？くらい。
`/dev/null`もよく見かけるので、特別な意味があるのは分かるけど、意味は分かっていません。

普段は基本UIで操作していて、bashはVS Codeのターミナルでたまに`cd`・`cat`・`mkdir`・`rm`・`touch`を打つとか、CLIの結果を`>`でファイルに書き込むくらい。

AIが作ったスクリプトとは、これからもずっと付き合っていくことになります。

`rm`みたいに消しそうなまずいコマンドの勘所はあるので、上書きや削除への恐怖はそこまでありません。
一方で、もし「これ何してるの？」と聞かれても、説明はできない。
ファイルの一覧を取るくらいなら分かりやすいけど、もうちょっと操作が多いものだと、「それが本当に正しいか？」を断言できないんです。

個人で使うなら問題ないけど、仕事でそれはまずいなと。
今ちょっと試す、くらいのスクリプトならまだいいけど、今後みんなに使ってもらうスクリプトを作りたいときには、理解していないといけないなと思いました。
中身が分からないまま使い続けるのではなく、このくらいのbashは自分で読めて書けるようになりたい！と思って、改めてbashの基礎を学ぶことにしました。

# 学習内容

## 課題の一覧

| 課題 | やったこと | 予想 |
|---|---|---|
| 1-1 | 変数を作る（`=`の前後に空白を入れると？） | ✗ 外れた |
| 1-2 | 空白の入った値を変数に入れる | △ 半分正解 |
| 1-3 | `"`あり・なしで値を渡す（`printf`と`touch`） | ✗ 外れた |
| 1-4 | `'`と`"`の違い | ○ 当たった |
| 1-5 | 自分で書く：変数だけでファイルに書き込む | ✗ `ambiguous redirect`でつまずいた |

予想が外れたところばかりだったので、課題の順に書いていきます。

## 1-1 変数を作る

```bash
$ greeting=hello
$ echo $greeting
hello
```

`名前=値`で変数に入れて、`$名前`で使います。
これは問題なし。

### `=`の前後に空白を入れたら、コマンドになった

ほかの言語だと`greeting = "hello"`と書くのがふつうなので、手癖で空白を入れたらエラーに。

```bash
$ greeting = hello
bash: greeting: command not found
```

bashは1行を受け取ると、**空白で区切って、いちばん最初のかたまりをコマンドの名前**、残りをそのコマンドに渡す値として読むそうです。

| かたまり | bashの読み方 |
|---|---|
| `greeting` | コマンドの名前 |
| `=` | 1つめの値 |
| `hello` | 2つめの値 |

つまり「`greeting`というコマンドに、`=`と`hello`を渡して実行して」と言われたと思って、そんなコマンドはないのでエラーになっていました。
`greeting=hello`は空白がないので1つのかたまりで、`名前=値`の形のかたまりは変数の設定として読まれます。

## 1-2 空白の入った値を変数に入れる

次は、空白の入った値です。

```bash
$ value=hello world
bash: world: command not found
```

`command not found`なのは、`"`で囲っていないから、空白のあとが続きの文字として認識されずに、引数だと勘違いされたのかな？と思いました。

半分正解でした。
エラーメッセージをよく見ると、`world`が**コマンド**だと思われています。

bashには`名前=値 コマンド`という書き方があって、「そのコマンドを実行するあいだだけ、変数をその値にして実行する」という意味になるそうです。

| 打ったもの | bashの読み方 |
|---|---|
| `value=hello world` | `value`を`hello`にして、`world`というコマンドを実行 |
| `value= hello world` | `value`を空にして、`hello`というコマンドに`world`を渡して実行 |

`value= hello world`は、自分が打ち間違えたときのものです。こっちは`hello: command not found`になりました。
どっちも、`名前=値`の次のかたまりがコマンドになっています。

`"`で囲めば、ちゃんと入りました。

```bash
$ value="hello world"
$ echo $value
hello world
```

## 1-3 `"`を付けなかったら、ファイルが2個できた

この変数を、`"`ありとなしで使ってみます。
自分の予想は「`"$value"`は`$value`という文字のまま、`$value`は`hello world`になる」でした。

`printf '[%s]\n'`は、受け取った値を1つずつ`[ ]`で囲んで表示するコマンドです。何個受け取ったかが見えます。

```bash
$ printf '[%s]\n' $value
[hello]
[world]
$ printf '[%s]\n' "$value"
[hello world]
```

ファイルを作る`touch`でも試しました。どちらも1個だけど、できるファイルの名前が違うと予想していました。

```bash
$ touch $value
$ ls
hello  world
$ touch "$value"
$ ls
 hello  'hello world'   world
```

`"`なしだと、ファイルが**2個**できました。

Claudeに聞いたら、bashは`$value`を見つけると、

1. まず`$value`を中身の`hello world`に置き換える
2. そのあと、`"`で囲まれていない部分を空白で区切る

という順番で動くそうです。

| 書き方 | 1. 置き換え | 2. 区切り | コマンドが受け取る値 |
|---|---|---|---|
| `$value` | `hello world` | される | `hello`と`world`の2個 |
| `"$value"` | `hello world` | されない | `hello world`の1個 |

`"`は「置き換えない」ではなく、「**置き換えたあとで区切らない**」という意味でした。

## 1-4 「そのまま」になるのは`'`

では、自分が予想した「`$value`という文字のまま」になるのは何かというと、`'`（シングルクォート）でした。これは予想が当たりました。

```bash
$ echo "$value"
hello world
$ echo '$value'
$value
```

| 書き方 | 中身に置き換える | 空白で区切る | 結果 |
|---|---|---|---|
| `$value` | する | する | `hello`と`world`の2個 |
| `"$value"` | する | しない | `hello world`の1個 |
| `'$value'` | しない | しない | `$value`という文字そのまま |

ここで、さっきの`ls`の表示を思い出しました。

```
 hello  'hello world'   world
```

この`'hello world'`の表記で、「シングルだとそのまま、ダブルだと区切らないなのか」と気づきました。
この`'`はファイル名の一部ではなく、「bashにこう打てば、この名前を1つの値として渡せますよ」という形で、`ls`が表示してくれているそうです。

## 1-5 `ambiguous redirect`が訳せなかった

ここまで分かったつもりで、自分で書く問題でつまずきました。

> 変数`file`に`my memo.txt`、変数`text`に`my first memo`を入れて、その2つの変数だけを使って、`text`の中身を`file`のファイルに書き込む。そのあと中身を表示して確かめる

ファイル名は、補完機能を使ったら空白の前に`\`がついて出てきたのでそのまま入れました。
これはエスケープと呼ばれるそうで、エスケープシーケンスみたいなものらしいです。
同義かと思ったらちょっと違うらしい。

```bash
$ file=my\ memo.txt
$ echo $file
my memo.txt
$ text="my first memo"
```

`<`の向きを間違えたりもしつつ、たどり着いたのがこれ。

```bash
$ echo $text > $file
bash: $file: ambiguous redirect
```

`ambiguous`って曖昧って意味だよな…曖昧なリダイレクトってなに？となりました。
`command not found`と違って、分かりづらい。

ヒントで、`cat`のエラーを見るように言われました。

```bash
$ cat $file
cat: my: No such file or directory
cat: memo.txt: No such file or directory
```

`my`と`memo.txt`の2つに分かれてる！
`touch $value`でファイルが2個できたのと同じことが起きていました。`"`で囲えてなくて、正しく認識されていないことに気づけなかったんです。
`>`の行き先が2つになって「どっちに書き込めばいいの？」というのが、「曖昧」の意味でした。

`"`で囲ったら、できました！
変数を`"`で囲むことにすごい違和感。

```bash
$ echo $text > "$file"
$ cat "$file"
my first memo
```

### `$text`も`"`で囲う

`echo $text`は`"`なしでも同じ結果になりましたが、これは`echo`が受け取った値を空白1つでつないで表示するからだそうです。
空白が2つ以上続く値だと、`"`なしでは詰まってしまうので、`$text`も囲っておくのが正解でした。

```bash
file="my memo.txt"
text="my first memo"
echo "$text" > "$file"
cat "$file"
```

# まとめ

- bashは1行を空白で区切って、最初のかたまりをコマンドの名前だと思う<br>`=`の前後に空白を入れると、変数ではなくコマンドとして実行される
- `名前=値 コマンド`は、そのコマンドのあいだだけ変数を設定する書き方<br>`value=hello world`は`world`がコマンドになる
- `"`は「置き換えたあとで区切らない」、`'`は「書いたとおりそのまま」
- `"`を付けないと値が分かれる。`ambiguous redirect`は、`>`の行き先が分かれて曖昧になったときのエラー
- `""`で囲う習慣がなかなかないので、「`$`を書いたら`"`で囲む」をいつもの形にしたい

これで、Claudeが作った冒頭のtry関数のうち、`echo "OK  $1 [$2]"`は、`"`の中なので`$1`と`$2`だけが置き換わる、というところまでは読めるようになりました。
